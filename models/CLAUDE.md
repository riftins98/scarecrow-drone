# models

Gazebo SDF simulation models for drone, sensors, and test targets. `launch.sh` keeps this repository as the source of truth and exposes these models to PX4/Gazebo through a clean symlink mirror under `px4/build/scarecrow_gz_models/`.

## Subdirectories
- `ceiling_net/` — **Unused (7.6MB).** Static chain-link ceiling mesh. It was written for a hangar world that no longer exists, and no world in `worlds/` includes it. Kept only because a roofed world would want it back; delete it if none is coming.
- `holybro_x500/` — Holybro X500 quadcopter frame with all sensors attached (optical flow, downward rangefinder, upward ceiling rangefinder, 2D lidar, mono camera). model.sdf defines the full drone including sensor plugins and keeps the flight sensors close to the frame so lidar/camera/rangefinder origins match the EKF sensor-offset configuration.
- `drone_view_cam/` — Collisionless camera sensor used only by `launch_with_stream.sh --drone_view`. The launcher injects it into a temporary `holybro_x500` overlay as a fixed link 1.5m behind and 0.5m above `base_link`, pitched 10 degrees downward, so it can clip through geometry without collision effects. Profile is 1280x720 at 15 Hz sim-time, matching `mono_cam_hd`. 15 Hz delivers ~10 Hz wall-clock at current RTF, which is what the streamer consumes -- rendering faster only produces frames that get discarded. Sharpness comes from resolution and encoder quality, not from update rate.
- `lidar_2d_v2/` — 2D scanning lidar sensor plugin (`gpu_lidar`, 1440 samples, 360 degrees, **`update_rate=5.5`**). Matched to the hardware: a Slamtec RPLidar A1M8 spins at 5.5Hz typical (2-10Hz adjustable) and samples 8000 points/second, i.e. 1455 per revolution — the 1440 samples were already right, only the rate was not. Deliberately slower than the simulator could manage, because at 30Hz the control loop saw a fresh scan nearly every tick while the drone will see one roughly every fourth, and tuning against 30Hz produces numbers the hardware cannot reproduce. Also ~5.5x less GPU raycasting. Not to be confused with the single-ray `lidar` sensor inside `holybro_x500/model.sdf` (`samples=1`, 50Hz), which is the downward rangefinder feeding PX4's EKF and is PX4's business, not ours.
- `mono_cam/` — Mono camera sensor plugin, 1280x720 at 15Hz. Left below the Pi Camera Module 3's capability (1536x864@120fps, 1080p@50fps) on purpose: nothing consumes more. YOLO manages ~24fps on MPS and the detector rate-limits to one inference per second, so a faster camera would render frames that are discarded. Topic: `camera_link/sensor/camera/image`.
- `mono_cam_hd/` — Fixed monitoring camera for the observer stream (not a flight/detection input). **1920x1080, `anti_aliasing=4`, `update_rate=6`**, streamed at 5fps. The browser stretches this to fill the viewport, so on a high-DPI display 720p was upscaled and looked soft; resolution is the fix, and it only became the right fix once MJPEG replaced WebRTC (aiortc capped bitrate at 1Mbps, so more pixels there meant thinner bits; that streamer has since been deleted). Render rate and stream fps had to drop together to pay for the pixels — render cost scales with resolution x update_rate, and on this stack **render rate costs more than resolution does**. That is the trade to remember before raising either.
- `military_drone/` — Alternative drone model for visual variety in testing
- `military_drone_half/` — Half-size visual/collision variant of `military_drone`, used by smaller hangar pursuit worlds to keep parked drone props visible while reducing their footprint.
- `pigeon_billboard/` — **Unused (596KB).** Flat billboard target with a pigeon image, from the retired garage worlds. `pigeon_3d/` replaced it; no current world includes it.
- `pigeon_3d/` — **The detection target (80MB).** Included by all four hangar worlds. This is what YOLO detects and the mission pursues; the mission teleports it rather than deleting it, because removing a model from a running Gazebo world segfaults.
- `tf_luna_up/` — Upward-facing TF-Luna single-ray rangefinder for ceiling clearance in roofed indoor worlds. `update_rate=100` to match the Benewake TF-Luna's default frame rate (configurable 1-250Hz); the simulator previously ran it at 50Hz, slower than the hardware. Topic: `tf_luna_up_link/sensor/ceiling_rangefinder/scan`.
- `yolo/` — YOLO model weights used by flight scripts: `best_v4.pt` (custom pigeon detector) and `yolov8s.pt` (general YOLOv8 small model used by the current hangar pursuit script with class filtering).
